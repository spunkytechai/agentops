# Product and Release Roadmap

This roadmap separates verified repository capabilities from work required for a dependable public release and future commercial operation. A green CI run is necessary but is not, by itself, a stable-release decision.

## Current product foundation

The repository currently contains Python and TypeScript SDKs for:

- Agent registration and versioned registry storage.
- Deny-by-default tool policy with explicit deny precedence.
- Expiring, one-time, action-bound approval workflows.
- Execution lifecycle events and trace context.
- OTLP/HTTP JSON trace export with bounded metadata.
- Deterministic evaluation suites, run history, and baseline comparison.
- Subprocess and Docker worker adapters with resource limits and protocol validation.
- Shared cross-language conformance fixtures and automated tests.

See [Architecture](ARCHITECTURE.md), [Security Model](SECURITY_MODEL.md), and the root README for implementation details and limitations.

## Release gates

### Gate A — Reproducible engineering

- [ ] Commit `packages/typescript/package-lock.json` generated by the supported Node/npm toolchain.
- [ ] Change TypeScript CI installs from `npm install` to `npm ci`.
- [ ] Verify all Python versions, Node 20, and real Docker integration from the locked dependency graph.
- [ ] Review Dependabot major updates for runtime and platform compatibility.
- [ ] Verify clean builds and package contents for both SDKs.

Tracking: [Issue #30](https://github.com/spunkytechai/agentops/issues/30).

### Gate B — Security and reliability

- [ ] Independently review authorization, principal binding, approval lifecycle, fingerprinting, and replay protection.
- [ ] Review subprocess lifecycle, cancellation, byte limits, deadlines, and child cleanup.
- [ ] Review Docker flags, daemon trust, isolation, resource limits, and orphan cleanup.
- [ ] Review SQLite transaction semantics, cross-process behavior, and schema compatibility.
- [ ] Review telemetry data minimization, retention, and evaluation-data handling.
- [ ] Record findings by severity; remediate critical/high findings or document an explicit risk acceptance.
- [ ] Publish the security review summary and final release decision.

Tracking: [Issue #14](https://github.com/spunkytechai/agentops/issues/14). Keep this issue open until every release-gate criterion has evidence.

### Gate C — Developer experience and distribution

- [ ] Add a minimal end-to-end sample for each SDK.
- [ ] Verify installation from published artifacts, not only editable/local source.
- [ ] Add versioning and compatibility policy for public APIs and conformance fixtures.
- [ ] Publish signed/tagged releases and release notes.
- [ ] Add an upgrade guide and deprecation policy.
- [ ] Document supported operating systems, Node/Python versions, Docker requirements, and known limitations.

### Gate D — Commercial validation

- [ ] Interview 5–10 teams running tool-using AI agents.
- [ ] Run at least three scoped implementation pilots with measurable outcomes.
- [ ] Validate recurring demand for hosted evaluation history, team collaboration, and governance.
- [ ] Estimate hosting, storage, support, and security costs before setting subscription prices.
- [ ] Design a separate hosted control plane only after demand is evidenced.
- [ ] Complete tenant isolation, identity, billing, privacy, deletion/export, and incident-response reviews before hosted general availability.

Commercial model and validation hypotheses: [Commercialization Strategy](COMMERCIALIZATION.md).

## Suggested sequencing

| Sequence | Deliverable | Exit evidence |
|---|---|---|
| 1 | Lockfile and reproducible CI | `npm ci` and full matrix green |
| 2 | Independent security review | Published findings and verified remediation |
| 3 | Package/release engineering | Installable tagged Python and npm releases |
| 4 | Developer experience | End-to-end examples pass from clean environments |
| 5 | Design-partner pilots | Customer-approved outcome evidence |
| 6 | Hosted-service decision | Repeated demand, cost model, security architecture |

## Release status language

- **Experimental:** APIs may change; not recommended for critical production workloads.
- **Release candidate:** feature scope is frozen; release-gate tests and reviews are underway.
- **Stable:** only after Gates A–C pass, the independent security review is complete, and the release decision is documented.
- **Hosted commercial availability:** only after Gate D's service-specific security and operational controls pass.

Do not infer stable or production-ready status from a passing CI badge alone.
