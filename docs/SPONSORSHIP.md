# Sponsor AgentOps

AgentOps is an early-stage, open-source Python and TypeScript toolkit for governing AI-agent tool access, human approvals, evaluation, execution workers, and operational telemetry.

The core SDKs remain available under the Apache-2.0 license. Sponsorship funds maintenance of the public project: engineering, security work, compatibility, documentation, conformance testing, releases, and community support.

**GitHub Sponsors:** [github.com/sponsors/spunkytechai](https://github.com/sponsors/spunkytechai)

> The GitHub Sponsors profile for @spunkytechai has been approved and is public. Monthly and one-time tiers must still be configured in the Sponsors dashboard before supporters can select fixed contribution levels. The repository funding configuration does not itself configure tiers.

## What sponsorship funds

Sponsors help fund:

- Maintenance and security fixes across the Python and TypeScript SDKs.
- Cross-language conformance tests and reproducible releases.
- Documentation, examples, issue triage, and contributor experience.
- Independent security review and remediation work.
- Compatibility testing and CI infrastructure.
- Open development of agent governance and execution tooling.

Sponsorship does not purchase control over the project, access to customer data, influence over security decisions, or a guarantee that a requested feature will be built.

### Suitable in-kind support

- Cloud compute and storage credits.
- CI/CD and developer tooling credits.
- Security assessment or penetration-testing time from qualified providers.
- Model/API credits with clear usage limits and no requirement to expose private workloads.
- Documentation, accessibility, or developer-relations support.

In-kind contributions are accepted only after their scope, expiry, restrictions, renewal conditions, and fair value are documented. No sponsor receives access to secrets, private repositories, customer workloads, or unpublished vulnerability details through a sponsorship.

## Sponsor recognition policy

- Sponsors may be listed by name and logo only after receiving written permission and approved brand assets.
- Recognition is factual and does not imply endorsement, certification, or a customer relationship.
- Sponsors do not control the Apache-2.0 license, security findings, vulnerability disclosure, maintainer decisions, or project roadmap.
- No sponsor may require a security issue to be hidden, a vulnerability report to be delayed, or a competitor to be excluded from using the open-source project.
- Recognition may be removed if a sponsor's conduct creates legal, safety, or reputational risk.
- Public recognition is optional; anonymous sponsorship is respected.

## How to become a corporate sponsor

Contact the maintainers through a GitHub issue or the repository's public contact channel with:

1. Company and website.
2. Sponsorship type: cash, in-kind, or a combination.
3. Proposed amount and sponsorship period.
4. The open-source work you want to support.
5. Requested recognition and any procurement/compliance requirements.

Do not post bank details, tax identifiers, contracts, confidential security reports, or personal information in a public issue. Commercial arrangements should be handled privately and documented with an appropriate written agreement.

## Transparency and financial handling

- Publish periodic project updates describing funded work and measurable outputs.
- Keep sponsorship funds and records traceable and use them for the stated project-maintenance purpose.
- Do not claim sponsorships are charitable donations or tax-deductible.
- Sponsorship payments may have income-tax, GST, invoicing, withholding, and accounting implications. Confirm the correct treatment, contracting party, receipts, and any required registration with a qualified Indian chartered accountant before accepting corporate funds.
- GitHub Sponsors onboarding requires the account holder to complete GitHub's identity, banking, tax, and security requirements.
